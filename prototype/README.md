# 루멘병원 — 4개 지점 통합 병원 웹사이트 프로토타입

4개 지점 게이트웨이와 지점별 홈, 진료과 상세, 회원가입 없는 본인인증 진료 예약, 그리고 예약·콘텐츠·운영 환경을 관리하는 통합 관리자를 보여 주는 의료 반응형 웹사이트의 제안용 프로토타입입니다.

> 병원명·지점·주소·전화번호·의료진·환자·게시물·통계 수치는 모두 **시연용 가상 데이터**입니다. 실제 본인인증, 예약 접수, 문의 전송, 서버 연동은 이루어지지 않습니다.

## 여는 방법

- 시작 파일: 이 폴더의 `index.html`입니다. 정적 호스팅에 폴더 전체를 올리거나 로컬 브라우저에서 직접 열어 이용합니다.
- 로컬: 폴더의 `index.html`을 브라우저로 열면 됩니다. 설치나 서버가 필요 없습니다.
- 저장한 체험 데이터와 관리자 로그인 상태는 **현재 브라우저에 자동 저장되어 새로고침 후에도 유지됩니다.** 관리자 로그인 화면 하단의 「체험 데이터 초기화」로 처음 상태로 되돌립니다.
- 오른쪽 아래 **「체험 안내」**에서 주요 시나리오를 바로 실행할 수 있습니다.

## 시뮬레이션 범위

- **본인인증**: 모의 인증창이며 인증번호는 `123456`입니다. 실제 서비스는 귀사가 계약한 본인인증 기관과 연동합니다.
- **예약 저장 규칙**: 운영표·휴진·마감 시각 재확인, 정원 확인, 같은 시간 중복 예약 차단을 브라우저에서 서버 규칙처럼 재현합니다. 실제 구축에서는 서버와 DB가 이 규칙을 보장합니다.
- **운영 환경 (NCP)**: 구성·배포·백업 상태를 보여 주는 시연 화면이며 실제 클라우드 콘솔과 연결되지 않습니다.
- **지도·전화·문자**: 지도는 그림으로 대신했고, 전화 연결과 예약 안내 문자·알림톡은 동작하지 않습니다.
- **게시판 편집기**: 시연은 텍스트 입력이며, 실제 편집기는 구축 시 확정합니다.
- 화면의 과거 통계 추이는 가상 수치입니다.

## 이번 검토에서 반영한 사항

- 딥 그린·아이보리·우드 톤으로 색상을 정리하고 생성한 라운지·진료실 사진을 메인·지점 홈·진료과·관리자 로그인에 배치했습니다. 이미지 2개의 합계는 약 187 KB입니다.
- 이용자 화면의 제안·구축 설명을 병원 이용 안내로 바꾸고, 모의 인증·가상 자료 안내는 인증창·체험 안내·푸터에서 유지했습니다.
- 본인인증 요청 당시의 정보·통신사와 완료 시점의 값을 비교하고 3분 유효시간, 실제 날짜 형식, 전화번호를 검사합니다.
- 개인정보는 화면 이동·계정 변경·로그아웃 시 다시 가립니다. 증상 메모는 사유 입력과 열람 기록을 거쳐 확인합니다. 하이픈 없는 전화번호도 가립니다.
- 관리자 작업의 계정·지점·게시글 범위를 다시 확인하고, 운영표의 잘못된 시각·겹치는 구간·정원·예약 규칙을 검사합니다.
- 단축 진료 종료 시각을 넘는 예약을 차단하고, 정원을 낮출 때 기존 예약 충돌을 알립니다.
- 경합·복구 모의 작업을 닫거나 화면을 이동하면 대기 작업을 취소합니다. 경합 시험의 임시 예약도 제거합니다.
- 통계 CSV를 실제 생성하고, 검수한 배포 버전 식별자를 운영 반영 시 그대로 유지합니다.
- 모달의 키보드 초점 이동·Escape 닫기·배경 스크롤, 숨김 속성, 예약 URL 입력값, 팝오버 위치와 작은 화면의 줄바꿈을 보완했습니다.

## 배너·팝업과 지점 정보 편집

1. 관리자 로그인 후 **콘텐츠 → 배너·팝업 → 배너·팝업 등록**을 선택합니다. 유형, 제목·안내 문구, 색상, 노출 기간·지점, 이동 화면을 입력하고 등록합니다. 기존 항목은 **수정** 버튼으로 편집합니다.
2. 전 지점 공통 배너는 전체 홈과 각 지점 홈, 지점별 배너는 해당 지점 홈에 표시합니다. 팝업은 전체 또는 해당 지점 홈에서 기간에 맞춰 표시하며, 해당 지점 전용 팝업을 공통 팝업보다 우선합니다. 「오늘 하루 보지 않기」를 선택한 날은 팝업을 다시 띄우지 않습니다.
3. **콘텐츠 → 지점·진료과 → 지점 정보 → 수정**에서 소개·주소·전화·주차·대중교통·층별 안내를 수정합니다. 지점 홈·오시는 길·예약 안내·푸터의 관련 정보가 같은 데이터로 갱신됩니다.
4. 전체 관리자는 모든 항목을, 지점 관리자는 자기 지점 전용 배너와 기본 정보를 수정합니다. 전 지점 공통 또는 여러 지점에 걸친 배너, 진료과 운영 구성은 전체 관리자만 변경합니다.
5. 저장과 노출 전환은 처리 기록에 남습니다. 취소한 입력은 반영하지 않으며, 잘못된 날짜·전화번호·글자 수·노출 지점은 저장 전에 검사합니다. 입력한 HTML은 실행되지 않고 텍스트로 표시합니다.
6. 저장한 변경은 현재 브라우저의 로컬 저장소에 유지됩니다. 다른 브라우저·기기와 공유하거나 실제 서버에 저장하지는 않습니다. 초기화하면 기본 가상 자료와 로그아웃 상태로 돌아갑니다.

## 연속 사용 검토에서 보완한 사항

- 탭을 자정 이후까지 열어 두어도 예약 가능 날짜·당일 마감·대시보드를 현재 날짜로 계산합니다. 기존 가상 데이터 생성 기준일과 실제 조회 기준일을 구분합니다.
- 접수된 예약을 조회·취소한 뒤 완료 화면으로 돌아가도 현재 상태에 맞는 문구와 아이콘을 표시합니다.
- 선택한 날짜가 지난 뒤 예약을 제출하면 날짜·시간 선택 단계로 돌아가 새 일정을 선택하도록 합니다.
- 지도·운영 설정 안내의 제안용 표현과 중복된 문구를 간결하게 정리했습니다. 기존 사진과 색상 구성을 유지했습니다.

## 체험 데이터 유지와 초기화

- **자동 저장 대상**: 예약과 처리 이력, 문의·답변, 게시물, 배너·팝업, 지점 기본 정보·운영 진료과, 예약 스케줄·휴진 일정, 관리자 작업 기록, 모의 운영 환경·배포·복구 결과, 관리자 체험 로그인과 글자 크기입니다.
- **작성 중인 내용**: 예약의 지점·진료과·날짜·시간·메모, 미등록 문의의 이름·연락처·제목·내용도 복원합니다. 미저장 관리자 편집창 자체는 다시 열지 않습니다.
- **다시 확인할 항목**: 비밀번호·인증번호·인증창 진행 상태, 예약자 조회 인증과 관리자 개인정보 열람 상태는 저장하지 않습니다. 예약 진행 중 본인인증·동의는 새로고침 후 다시 진행합니다.
- **저장 위치**: `assets/store.js`가 이 프로젝트 전용 키 `lumen-demo:2026102702:v1`로 localStorage에 저장합니다. 데이터를 서버로 전송하지 않습니다. 실제 개인정보를 입력하지 마세요.
- **초기화 위치**: 관리자 로그인 화면 → 체험 계정 아래 → 「체험 데이터 초기화」. 로그인하지 않아도 이용할 수 있습니다. 확인 후 이 프로젝트의 저장 데이터·로그인 상태·팝업 숨김 설정을 지우고 로그인 화면을 다시 엽니다. 다른 사이트의 저장 키는 삭제하지 않습니다.
- **저장소 오류**: 접근 제한·용량 초과로 저장할 수 없으면 저장 안내와 알림으로 알립니다. 잘못된 형식·지원하지 않는 버전의 자료는 적용하지 않고 기본 화면과 초기화 안내를 표시합니다.
- **다른 탭**: 같은 저장소를 사용하는 탭에서 초기화가 감지되면 로그인 화면으로 돌아가 예전 상태를 다시 저장하지 않게 합니다. 일반 편집 내용을 여러 탭에서 실시간 동기화하는 기능은 제공하지 않습니다.
- 브라우저 사이트 데이터를 직접 삭제하거나 다른 브라우저·프로필로 열면 저장된 내용을 이어 볼 수 없습니다. 파일 주소에서의 localStorage 사용 가능 여부는 실제 이용 브라우저 설정에 따라 달라질 수 있으며, 실제 브라우저 검수는 아래 한계를 따릅니다.

## 진료 일정 표시 재검토

- 의료진 일정표가 시간 구간의 개수로 오전·오후를 판단하던 문제를 수정했습니다. 오후만 운영하거나 휴식 없이 연속 진료하는 일정, 예약 한 회분보다 짧은 구간을 실제 예약 시간 기준으로 구분합니다. 의료진별 기존 오후 휴진 설정은 유지합니다.
- 일요일 운영 설정을 의료진·지점 시간표에 반영하고, 야간 표시는 저장한 종료 시각에 따라 계산합니다. 지점 시간표에는 기준 진료과와 실제 구간을 표시하며, 휴진·단축 일정은 예약 화면에서 확인하도록 안내합니다.
- 시간표 제목이 길면 작은 화면에서 줄바꿈할 수 있도록 보완하고, 중복되거나 문장이 끊긴 안내 문구를 정리했습니다. 기존 이미지·색상·전체 구성은 유지했습니다.
- 위 일정 변경 사례의 회귀 검사 2건과 화면 상태 4개를 추가했습니다. 실제 브라우저 배치 검수는 아래 제한과 동일합니다.
